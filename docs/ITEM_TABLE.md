# Таблица предметов: извлечение и патч

Характеристики предметов не лежат ни в одном файле данных. Они вкомпилированы в
`dlords.exe`. Документ описывает, как устроена таблица, что означают её поля и
как их менять.

Инструменты: `dl_toolkit.itemtab` (извлечение), `dl_toolkit.itempatch` (патч),
команды `dl items` и `dl items-patch`.
Выгрузка таблицы: [`reference/item_table.csv`](reference/item_table.csv).

---

## 1. Где на самом деле лежат предметы

В `dlords.exe` **нет строки** `D6ITEM` или `ITEM.DAT` — ни в каком регистре.
Для контроля: `D6MONS.DAT`, `D6TRLIST.DAT`, `D6PROP.DAT`, `MONSOUND.DAT` в
образе присутствуют. Значит `D6ITEM.DAT` движком не открывается.

Таблицу строит функция `MakeITEMS()` — 19 984 инструкции, ~116 КБ кода,
заполняющие статический массив непосредственными записями:

```asm
mov  ecx, dword ptr [0x0065BA6C]   ; "CHAIN MITTENS" из .rdata
mov  dword ptr [0x030DF5A4], ecx   ; имя записи 2
mov  bp, 1                          ; часть значений идёт через регистры
mov  word  ptr [0x030DF4F8], bp
mov  word  ptr [0x030DF5CC], 0x68  ; иконка записи 3
mov  dword ptr [0x030DF5E0], 0x2EE ; цена записи 3
```

| Параметр | Значение |
|---|---|
| Функция | `MakeITEMS()`, VA `0x004ED670`…`0x00509DF1` |
| База массива | `0x030DF40C` |
| Шаг записи | 204 байта |
| Записей | 948 (индексы 0…947) |
| Размер массива | 193 392 байта |
| Найдено присваиваний | 10 058 (плюс 400 нераспознанных) |
| Записей с именем | 510 |

Значения пишутся двумя способами — непосредственным операндом и через регистр.
Без пропагации констант по коду теряется около 60 % полей, поэтому извлечение
выполняет линейную интерпретацию `mov`/`xor` с отслеживанием регистров.

## 2. Соответствие с `iname.dat`

**`iname_id = индекс + 1`**

| `iname.dat` id | индекс | имя |
|---:|---:|---|
| 1 | 0 | PUNCH |
| 2 | 1 | BAT BITE |
| 3 | 2 | CHAIN MITTENS |
| 4 | 3 | CHAIN BOOTS |

Проверено строго: из 510 записей с заданным именем **510 совпали** с
`iname.dat[idx + 1]`, ни одного расхождения. Соседние сдвиги дают 13–16
совпадений — случайный шум.

### Это закрывает старую загадку

Все предыдущие отчёты фиксировали противоречие: `iname.dat` id 4 = `CHAIN BOOTS`,
а `D6ITEM.DAT` запись 4 = `Vampire's Bite`, и делали вывод «разные пространства
id, мост не найден».

Мост не найден потому, что его нет: `D6ITEM.DAT` — не таблица предметов.
Она содержит другой набор (`swings at $`, `Willow Arrow`, `Heal Potion`) —
по-видимому, данные более ранней версии движка, оставшиеся в поставке.
Редактирование этого файла ни на что не влияет.

## 5. Записи без характеристик

438 записей код не трогает — они остаются нулевыми. Это алхимические реагенты и
рунные камни: `BAT WING`, `RAT TAIL`, `WOLF MANE`, `SNAKE SKIN`, `RAVEN CLAW`,
`AENIR`, `BRUENGULD`, `CYTHOEN`… Им характеристики не нужны: они существуют
только как имя и id для рецептов и торговых списков.

Второго инициализатора в образе нет. Сканирование всей секции `.text` находит
обращения к массиву только внутри `MakeITEMS` и в 99 мелких местах, читающих
отдельные предметы в рантайме (11 из них — индексная адресация `imul reg, 0xCC`).

## 6. Патч характеристик

Значения записаны непосредственными операндами, поэтому правка не меняет длину
инструкции: ни перемещений, ни релокаций. Патч механический и обратимый.

### План

```yaml
patches:
  - name: KATANA
    field: price
    value: 2000
  - name: SHORT BOW
    field: price
    value: 120
```

### Применение

```bash
dl items --find katana                        # посмотреть текущее
dl items-patch plan.yaml                      # сухой прогон
dl items-patch plan.yaml --write              # запись, оригинал в .dl_backup/
dl restore dlords.exe                         # откат
```

Вывод сухого прогона:

```
┌──────────────┬───────┬──────┬────────┬──────────┬────────────┐
│ предмет      │ поле  │ было │ станет │ смещение │ инструкция │
├──────────────┼───────┼──────┼────────┼──────────┼────────────┤
│ 460 KATANA   │ price │ 1000 │ 2000   │ 0xFD30F  │ 0x004FD309 │
│ 84 SHORT BOW │ price │ 50   │ 120    │ 0xEEFBE  │ 0x004EEFB8 │
└──────────────┴───────┴──────┴────────┴──────────┴────────────┘
проверка повторным разбором образа: пройдена
изменяется байт: 3
```

После применения образ разбирается заново и фактические значения сверяются с
запрошенными. Расхождение — ошибка, запись не выполняется.

### Что патчер отклоняет и почему

| Случай | Причина |
|---|---|
| Поле пришло через регистр | Регистр разделяется несколькими предметами; правка сломала бы соседей |
| Поле не инициализируется | Патчить нечего, значение остаётся нулевым |
| Значение не помещается в ширину поля | Затёрло бы соседнее поле |
| Поле `name` | Имя копируется из `.rdata`; отображаемое имя правится в `iname.dat` |
| Два патча на одну инструкцию | Второй молча отменил бы первый |

Отклонения — явные ошибки с указанием предмета, поля и адреса инструкции.

## 7. Ограничения

* **Добавить предмет нельзя.** Массив на 948 записей, заполняется линейным
  кодом. Новая запись требует вставки инструкций и сдвига кода.
* **Переименовать через патч нельзя.** Внутреннее имя копируется из `.rdata`
  и ограничено длиной исходной строки. Отображаемое имя берётся из `iname.dat`
  и правится напрямую, без патча exe.
* **400 присваиваний не распознаны** — значения из регистров, испорченных
  арифметикой. На известные поля это не влияет, но полная реконструкция
  массива неполна.
* **Патч ломает целостность exe.** Если `protect.dll` проверяет контрольную
  сумму, пропатченный образ может не запуститься. Проверять в виртуальной
  машине, откат — `dl restore dlords.exe`.
