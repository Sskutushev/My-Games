# Архитектура тулкита

Документ объясняет, почему код разложен именно так, и какие правила нельзя нарушать.

---

## 1. Задача, из которой всё следует

Мы редактируем данные закрытого коммерческого рантайма 2004 года. Из этого три следствия:

1. **Ошибка необратима.** Неверно собранный `D6ITEM.DAT` — это порванная установка и,
   возможно, порванные сейвы. Нужны резервные копии, атомарная запись и манифест.
2. **Проверить корректность нечем.** Спецификаций нет, исходников нет, отладчика в
   рантайме нет. Единственный объективный критерий — `encode(decode(x)) == x`.
3. **Знание неполно и будет меняться.** Семантика половины числовых полей неизвестна.
   Код обязан сохранять непонятое, а не «нормализовать» его.

Отсюда все решения ниже.

## 2. Слои

```
       cli            пользовательский интерфейс, форматирование вывода
        │
     content          предметная модель новой игры, валидация дизайна
        │
      verify          round-trip как предусловие любой записи
        │
       game           файловая система: бэкап, атомарная запись, манифест
        │
      schema          измеренные параметры таблиц конкретной сборки
        │
      codecs          чистые decode/encode на каждый формат
        │
      binio           примитивы: LE-числа, CP1251, фиксированные строки
```

Зависимости строго вниз. `binio` не знает про игру. `codecs` не знают про файлы.
`content` не знает про двоичные форматы.

### Почему кодеки не открывают файлы

`Codec.decode(bytes) -> Model` и `Codec.encode(Model) -> bytes` — чистые функции.
Это даёт три вещи, недостижимые при `decode(path)`:

* тесты на синтетических данных без установленной игры;
* `roundtrip_ok(data)` как однострочная проверка на любом байтовом массиве;
* возможность работать с данными из архивов и из памяти, когда контейнеры `SFFS`
  будут вскрыты.

### Почему модели хранят сырые байты

`FixedRecord` держит `name_raw: bytes`, а не `name: str`. Причина конкретная: в
оригинальных таблицах после `NUL` внутри поля имени лежит мусор от предыдущего
содержимого записи. Декодирование в `str` с последующей добивкой нулями теряет
эти байты, и round-trip разваливается. Сырое хранение делает запись точной, а
перекодировка происходит только когда имя действительно меняют.

Тот же принцип в `ScriptLine.trailing` (байты после `NUL` в блоке скрипта) и в
`SoundRegistry.raw_lines` (исходные строки конфига с комментариями и табуляциями).

**Правило: то, чего мы не понимаем, переносится байт в байт, а не переписывается.**

## 3. Round-trip как контракт

`dl verify` прогоняет `encode(decode(x)) == x` по всем поддерживаемым файлам
установки. На эталонной сборке Dungeon Lords v1.5 — **169/169**, включая все 158
скриптов NPC.

Проверка нашла реальную ошибку проектирования: первая версия строкового кодека
дедуплицировала одинаковые строки в куче. Файлы получались на 4–16 % короче
оригиналов. Оригинальный упаковщик дедупликацию не делает — и это стало известно
только из round-trip. Дедупликация осталась опцией `intern=True`, но по умолчанию
выключена, а в докстринге записано почему.

Без этой проверки ошибка ушла бы в игру и проявилась бы как повреждённые
смещения строк неизвестного происхождения.

## 4. Безопасность записи

`GameRoot.write()` выполняет три действия в фиксированном порядке:

1. Копирует оригинал в `.dl_backup/<путь>`, если копии ещё нет — повторные записи
   не затирают первоначальное состояние.
2. Пишет во временный файл и делает `Path.replace()` — атомарную замену.
   Прерывание процесса не оставляет полуфайла.
3. Дописывает в `.dl_backup/manifest.json` запись с временем, SHA-256 до и после
   и размером.

Откат: `dl restore <файл>`.

## 5. Границы знания зафиксированы в типах

`schema.py` хранит **измеренные**, а не предполагаемые параметры:

```python
TableSpec("D6ITEM.DAT", 284, 22, 22, 858, "предметы, экипировка и описания атак")
```

`content/models.py` кодирует ограничения движка константами:

```python
RACE_SLOTS = 16      # rd6string.dat 1300-1315
CLASS_SLOTS = 35     # rd6string.dat 1400-1434
SKILL_SLOTS = 45     # rd6string.dat 1800-1844
```

Свод правил новой игры валидируется против них при загрузке. Тест
`test_shipped_ruleset_matches_engine_layout` падает, если дизайн вырос за рамки
движка — до того, как что-либо будет записано в игру.

## 6. Данные дизайна: генерация и миграции

### Генерация

Матрица «35 классов × 45 навыков» — 1575 ячеек. Вести её вручную нельзя: любое
изменение профиля гильдии требует согласованной правки десятков строк.

Поэтому `tools/generate_ruleset.py` выводит матрицу из компактных правил:
профиль гильдии + акцент класса + ступень. YAML — артефакт сборки, который
коммитится. CI перегенерирует его и падает, если результат разошёлся с
закоммиченным.

### Миграции

Файлы в `data/` живут дольше кода. Каждая версия схемы получает функцию перехода
`vN -> vN+1`:

```python
MIGRATIONS: dict[int, Migration] = {1: _v1_to_v2}
```

Правила:

* миграция чистая — не мутирует вход, возвращает новый документ;
* применяется последовательно, пропуски версий запрещены;
* если миграция забыла поднять `schema_version`, это ловится и падает с ошибкой;
* понижение версии не поддерживается — откат делается через git.

`dl migrate` по умолчанию делает сухой прогон, запись — только по `--write`.

## 7. Тесты

91 тест, покрытие 99 %.

| Уровень | Что проверяется |
|---|---|
| Синтетические данные | Каждый кодек: round-trip, редактирование, все ветки ошибок |
| Файловая система | Бэкап, атомарная запись, манифест, откат — на `tmp_path` |
| Модель дизайна | Все правила валидации, включая перекрёстные ссылки класс↔навык |
| Миграции | Переход, идемпотентность, все аварийные случаи |
| CLI | Коды возврата и вывод через `typer.testing.CliRunner` |
| Реальная игра | Маркер `gamedata`: round-trip 169 файлов установки |

Тесты с маркером `gamedata` пропускаются, если `DL_GAME_ROOT` не задан. В CI они
не выполняются — файлы игры в репозиторий не входят. Локально они и есть главная
проверка проекта.

Отдельно проверяется то, что раньше было ошибкой: тест
`test_fixedtab_preserves_garbage_after_terminator` фиксирует сохранение мусора
после `NUL`, а `test_strtab_does_not_intern_by_default` — отсутствие
дедупликации.

## 8. Конвейер качества

| Проверка | Инструмент | Настройка |
|---|---|---|
| Формат | `ruff format` | длина строки 100 |
| Линт | `ruff check` | E, W, F, I, UP, B, C4, SIM, PTH, RUF, ANN, TID |
| Типы | `mypy --strict` | послабления только для `tests.*` |
| Тесты | `pytest` + `pytest-cov` | порог покрытия 90 % |
| Миграции | `dl rules`, `dl migrate` | плюс сверка сгенерированных данных |
| Сборка | `python -m build`, `twine check` | установка wheel и запуск `dl version` |

CI гоняет всё на Python 3.11 и 3.12. Локально то же самое доступно через
`pre-commit install`.

Правила `RUF001`/`RUF002`/`RUF003` («неоднозначные символы») отключены осознанно:
документация и сообщения об ошибках на русском, эти правила дают сплошные ложные
срабатывания на кириллице.
